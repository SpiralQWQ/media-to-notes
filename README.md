<h1 align="center">media-to-notes</h1>

<p align="center">Turn any content — video, image album, or text — into AI teaching notes.</p>
<p align="center">Drop a link or a local path. It downloads, transcribes/OCRs, and produces a note ready to feed an AI teacher.</p>
<p align="center">Sources: Douyin · YouTube · Bilibili · local files &nbsp;|&nbsp; <a href="https://github.com/SpiralQWQ/media-to-notes">GitHub</a> · <a href="https://gitee.com/Spiral_QWQ/media-to-notes">Gitee mirror</a></p>

<p align="center"><b>Status: currently supports Douyin (video / image / text) and local files (video / image / text). Other platforms (YouTube, Bilibili, …) are not yet tested — stay tuned.</b></p>

## 🚀 Quick Start

```bash
git clone https://github.com/SpiralQWQ/media-to-notes.git
cd media-to-notes
pip install -r requirements.txt
python setup.py                    # one-time wizard → writes .env (answer 9 questions)
python scripts/media_to_notes.py "https://v.douyin.com/XXXXXX" --detect   # download + detect type
python scripts/media_to_notes.py --glm no                                  # transcribe + OCR (free)
```

Then hand the generated transcription/OCR text to Claude (or any AI) to write the AI teaching note per `spec/note_style_spec.md` — full flow in [Usage](#usage). Prerequisites (ffmpeg, douyin downloader, login Cookie, optional GLM key) are in [Installation](#installation).

> 🎬 Video · 🖼️ Image album · 📄 Text — from Douyin / YouTube / Bilibili / local files.

## What It Does

media-to-notes turns a Douyin / YouTube / Bilibili link or a local file into a structured "AI teaching note": a Markdown document an AI can read and then teach from, complete with overviews, knowledge points, Feynman questions, and a glossary. The pipeline runs in two CLI stages — download and detect, then transcribe/OCR — and the note itself is generated by Claude following the style spec in `spec/note_style_spec.md`.

| | Component | What it does |
|---|---|---|
| 📥 | Multi-source download | Douyin via jiji262 douyin-downloader (watermark-free, needs a Cookie); local files used as-is; YouTube/Bilibili via yt-dlp (implemented, not yet fully tested) |
| 🔍 | Type auto-detection | Detects whether the item is a video, an image album, or text, then routes it to the matching pipeline |
| 🗣️ | ASR transcription | fsmn-vad segments the audio, SenseVoiceSmall transcribes each segment so timestamps survive |
| 🖼️ | Multi-frame OCR | Extracts one frame per second (capped at 1200 frames) and runs OCR on every frame — free |
| 👁️ | Key-frame GLM | Optional `--glm yes`: only frames with real content change are sent to glm-4.6v-flashx, so the paid API bill stays low |
| 📝 | AI teaching-note generation | Claude reads the transcription/OCR/GLM text and writes the note per `spec/note_style_spec.md` |
| 📁 | Folder routing | Every item lands in `{category}/{date}/{seq}_{date}_{summary}_{size}`; sequence restarts at 00 each day |
| ✏️ | Correction dictionaries | `corrections.json` auto-fixes ASR mishears; `ocr_corrections.json` is a reference dictionary used while generating the note (OCR misreads are corrected against context, not auto-applied) |
| 🧹 | Cleaning engine | JSON kept-structure cleaning + per-frame visual cleaning (strip UI watermarks / tags / garbled text, keep timestamps) |
| 🕐 | Timeline interleave | Transcription + frames interleaved by timestamp into a half-ready Markdown — visuals stay aligned with speech |
| 🛠 | Upgraded wizard | `wizard.py` interactive setup (OCR interval / GLM / naming / course rules), answer-and-go |

```
  │   local           → use the path directly                   │
  └─────────────────────────────────────────────────────────────┘
          │
          ▼

  │                            + multi-frame OCR ─(+GLM key frames)
  │                            → clean (built-in: JSON + per-frame visual)
  │                            → interleave (transcript + frames → half-ready md)
  ├──────────► 🖼️ image album ─► OCR per image ─(+GLM per image)
  │
  └──────────► 📄 text ──► clean and structure directly
          │
          ▼
  ┌─────────────────────────────────────────────────────────────┐

  │          (or the half-ready interleaved md) and writes the  │
  │          AI teaching note per spec/note_style_spec.md       │
  └─────────────────────────────────────────────────────────────┘
          │
          ▼
  NoteBooks/<date>/<seq>_<date>_<summary>_<size>.md
```

## Installation

Prerequisites:

| Dependency | Version | Notes |
|---|---|---|
| Python | 3.10+ | Scripts use `dict \| None` union syntax |
| ffmpeg / ffprobe | any recent | Must be on PATH; used for audio extraction and frame extraction |
| jiji262 douyin-downloader | latest | Douyin only; needs a login Cookie |
| Separate venvs | optional | Downloader / FunASR / PaddleOCR can each run in their own environment |

Steps:

1. **Clone the repository.**

   ```bash
   git clone https://github.com/SpiralQWQ/media-to-notes.git
   cd media-to-notes
   # or from the Gitee mirror:
   # git clone https://gitee.com/Spiral_QWQ/media-to-notes.git
   ```

2. **Install Python dependencies.**

   ```bash
   pip install -r requirements.txt
   ```

   The ASR stack (funasr, modelscope) and OCR stack (paddleocr, rapidocr-onnxruntime) are heavy. They can live in dedicated venvs — point `DD_ASR_PY` / `DD_OCR_PY` / `DD_DL_PY` at the right interpreter, or install everything into one environment and skip those variables.

3. **Run the setup wizard (recommended).**

   ```bash
   python setup.py
   ```

   Answer 9 questions (use case / data root / OCR frequency / GLM vision / note language / transcription appendix / Feynman-question density / intermediate files / note organization) and it writes `.env` (read by the scripts) and `spec/user_prefs.md` (followed by Claude when generating notes). **No docs needed up front — answer and go.** Re-run anytime to change settings.

4. **Install ffmpeg** and add ffmpeg/ffprobe to PATH.

5. **Configure environment variables.** Copy `.env.example` to `.env`. The scripts load it automatically via `python-dotenv` (already in requirements.txt). All variables are optional — the scripts infer defaults from their own location. (Skip this step if you used `setup.py` — it already wrote `.env`.)

   | Var | Purpose | Default |
   |---|---|---|
   | `DD_BASE` | project data root (视频/, 音频/, 图片/, 文本/, NoteBooks/, temp/) | repo root |
   | `DD_DL_PY` | Python interpreter for douyin-downloader | current interpreter |
   | `DD_DL_SRC` | path to douyin-downloader source (contains run.py) | `<repo>/douyin-downloader` |
   | `DD_ASR_PY` | Python interpreter for FunASR | current interpreter |
   | `DD_OCR_PY` | Python interpreter for OCR scripts (RapidOCR / PaddleOCR) | current interpreter |
   | `DD_YTDLP` | yt-dlp executable (default `yt-dlp`; only needed for non-Douyin links) | `yt-dlp` |
   | `GLM_API_KEY` | BigModel API key, only needed for `--glm yes` | unset |
   | `OCR_INTERVAL` | video OCR frequency: seconds (`1`=1 fps, `0.5`=2 fps) or `scene`=on change / `no`=off | `1` |
   | `GLM_MODE` | GLM vision: `yes`=key-frames only (cheap) / `all`=every frame (expensive) / `no`=off | `no` |
   | `NOTE_LANG` | note body language: `zh`=Chinese / `en`=English / `auto`=follow content | `zh` |
   | `KEEP_APPENDIX` | keep full transcription appendix at note end: `true` / `false` | `true` |
   | `FEYNMAN_DENSITY` | Feynman question density: `10`=10/8/6, `6`=6/4/3, `0`=none | `6` |
   | `KEEP_MIDDLE` | keep intermediate files in cache: `true` / `false` | `true` |
   | `NOTE_ORGANIZE` | note directory: `date`=by date / `topic`=by course/subject | `date` |

6. **Install the Douyin downloader.** Clone [jiji262/douyin-downloader](https://github.com/jiji262/douyin-downloader) into the repo root so `douyin-downloader/run.py` exists (or set `DD_DL_SRC` to its source directory):

   ```bash
   git clone https://github.com/jiji262/douyin-downloader.git
   ```

7. **Set the Douyin Cookie.** The downloader needs a login cookie. Run `scripts/get_douyin_cookie.bat` (it opens a browser to log in and saves the cookie to `douyin-downloader/config.yml`, local only) or follow that repository's README. When it expires, re-run the helper — no re-install needed.

8. **Optional: get a `GLM_API_KEY`** from the BigModel open platform if you plan to use `--glm yes`.

> For YouTube / Bilibili / other links, also install `yt-dlp` (`pip install yt-dlp`). Local video/image/text paths need no downloader.

## Usage

The flow is two CLI stages plus note generation.

**Stage 1 — download and detect:**

```bash
python scripts/media_to_notes.py "https://v.douyin.com/XXXXXX" --detect   # Douyin
python scripts/media_to_notes.py "https://www.youtube.com/..." --detect   # yt-dlp
python scripts/media_to_notes.py "C:\path\to\video.mp4" --detect          # local file
```

The source is routed automatically: Douyin links go to jiji262 douyin-downloader, other links (YouTube/Bilibili/…) to yt-dlp, and local paths are used directly. It detects the type, routes it to 视频/ or 图片/ (文本/ for text), extracts a mono 16 kHz WAV from videos into 音频/, writes `temp/current_job.json`, prints the detected type, and asks whether to enable GLM vision analysis.

**Stage 2 — transcribe / OCR (with or without GLM):**

```bash
python scripts/media_to_notes.py --glm yes   # add GLM vision (paid, optional)
python scripts/media_to_notes.py --glm no    # OCR only (free, default)
```

The stage-2 pipeline per detected type:

| Detected type | Stage-2 pipeline | Generated files |
|---|---|---|
| 🎬 Video | FunASR transcription (fsmn-vad + SenseVoiceSmall) + multi-frame OCR (1 frame/s, capped at 1200 frames; RapidOCR); `--glm yes` adds key-frame GLM descriptions | `<audio>/<summary>.json`, `<video>/<summary>_visual.txt` |
| 🖼️ Image album | OCR each image (PaddleOCR first, RapidOCR fallback); `--glm yes` adds a GLM description per image | `<image>/<summary>_ocr.txt` (+ `_glm.txt`) |
| 📄 Text | Cleaned and structured directly into the AI teaching note | `NoteBooks/<date>/<seq>_<date>_<summary>_<size>.md` |

**Stage 3 — generate the note.** The agent (Claude) reads the transcription, OCR, and GLM text, corrects obvious OCR errors against context, and writes the AI teaching note into `NoteBooks/<date>/` following `spec/note_style_spec.md`.

## Note Format

Every note follows `spec/note_style_spec.md` — an 8-field frontmatter in fixed order, then a structured body.

Frontmatter fields, in order: `title`, `source`, `author`, `duration`, `word_count`, `created`, `tags`, `type`.

- `tags` — minimum 6 entries; the first tag is `{source site}学习笔记`.
- `type` — always `{source site lowercase}-ai-teaching-note`.

| Source | First tag | type |
|---|---|---|
| Douyin | `抖音学习笔记` | `douyin-ai-teaching-note` |
| Bilibili (B站) | `B站学习笔记` | `bilibili-ai-teaching-note` |
| YouTube | `YouTube学习笔记` | `youtube-ai-teaching-note` |
| Other site | `{site}学习笔记` | `{site}-ai-teaching-note` |
| Text cleanup | `抖音学习笔记` (default) | `douyin-ai-teaching-note` |

Body structure:

```
# Title
> One-sentence summary
## 📚 Overview / Learning objectives / Prerequisites
## 🧠 Core knowledge points
   each point: definition · plain analogy · principle · example ·
               why it matters · common mistakes
## 📖 Glossary  (English | Chinese | plain explanation | original quote)
## ❓ Feynman questions  — 10 for core points, 8 for important, 6 for general
---
## 📄 Full transcription appendix (for AI verification)
```

Feynman questions are open-ended and drawn from four angles: restate to a beginner, make an analogy, apply or derive, and find the common misconception. OCR text must be corrected against context before it lands in the note — see `config/ocr_corrections.example.json`.

Style rules (mandatory): extremely detailed · clear and structured · plain-language analogies · professionally accurate (keep English terms alongside Chinese) · teachable (an AI can read the note and teach a total beginner from it).

## FAQ

<details>
<summary><strong>Douyin says the Cookie expired, or fails with an empty 200 / anti-crawl error — what now?</strong></summary>

Re-open the jiji262 douyin-downloader cookie-capture helper (the bat it ships) to grab a fresh login cookie, then re-run `python scripts/media_to_notes.py "<link>" --detect`. No re-install is needed.
</details>

<details>
<summary><strong>Does GLM vision cost money?</strong></summary>

Only when you pass `--glm yes`. OCR runs on every frame or image and is free. GLM (glm-4.6v-flashx) is a paid API. By default it is applied only to **key frames** — frames whose content changed most, auto-selected by `select_key_frames` — to keep the bill low. Set `GLM_MODE=all` in `.env` to analyze **every** frame instead (expensive). Use `--glm no` to skip it entirely; the notes still get full ASR plus OCR. Note `--glm no` always wins over `.env` — it is the explicit "free mode" switch.
</details>

<details>
<summary><strong>Which platforms are supported?</strong></summary>

Douyin, YouTube, Bilibili, and local files. Douyin uses jiji262 douyin-downloader (watermark-free, needs a Cookie); YouTube and Bilibili use yt-dlp; a local path is used as-is.
</details>

<details>
<summary><strong>Why does stage 1 ask about GLM before stage 2?</strong></summary>

Stage 1 reports the detected type so you can decide whether to spend money on GLM vision. The default pipeline (OCR only) is free; GLM adds paid scene understanding on top. Asking first keeps that cost explicit.
</details>

<details>
<summary><strong>Transcription or OCR came out wrong — how do I correct it?</strong></summary>

ASR mishears go into `scripts/corrections.json` (example: `"get up"` → `"github"`) and are applied automatically when the transcript is built. OCR misreads are fixed during note generation against context; you can seed `scripts/ocr_corrections.json` as a reference dictionary for the generator. Copy the examples from `config/` into `scripts/` and add entries.
</details>

<details>
<summary><strong>Can it handle plain text?</strong></summary>

Yes. A local text path is treated as a 📄 text item, cleaned up, and structured directly into an AI teaching note — no ASR or OCR involved.
</details>

# AI 教材笔记 · 风格规范 v1.0

> 用户 2026-08-03 明确要求。生成任何学习笔记都必须遵守。
> 目标读者：**一无所知的零基础学生**。笔记用途：**喂给 AI，让 AI 照着笔记教学生**。

## 五大铁律

1. **特别详细** —— 宁可长不可短，覆盖全部知识点，不留空白。
2. **清晰有条理** —— 逻辑流程顺，不绕弯子；结构分明（编号分节）。
3. **通俗易懂** —— 善用类比/比喻，把抽象概念变成生活化画面。
4. **专业准确** —— 保留专业词汇（含中英对照），表述严肃严谨，不因通俗而失真。**OCR 图片识别可能有错**：生成笔记时必须结合上下文纠正明显错别字/乱码/误识（如英文单词、专业术语、数字），可参考 `scripts\ocr_corrections.json` 词典。
5. **可教学** —— AI 读完这份笔记，能照本宣科把学生讲懂、答得了追问。

## 铁律补充（v1.1，2026-08-09 新增）

### 重要性规则（防均匀摘要）
- 知识点分三级用力，**禁止平均用力**：
  - **核心**（定义、关键公式、算法步骤、数字结论）→ 详细展开 + 费曼题核心 10 道
  - **重要**（支撑性概念、应用场景）→ 中等展开 + 费曼题 8 道
  - **一般**（背景、延伸、例子补充）→ 简略 + 费曼题 6 道
- **数字、定义、术语必须保留原值**，不得因"概括"而丢失或四舍五入。

### [unclear] 规则（防 AI 编造）
- 转写/OCR 不确定、听不清、看不清处，**如实标注 `[unclear]`**。
- **严禁**用上下文脑补、猜测、编造不确定内容。
- 若某知识点完全无法从转写/OCR 确认，写"（此段转写不清，待核对原视频）"并标 `[unclear]`。

### 三分法分节（可检索）
- 每讲笔记正文按三块组织（可嵌套在章节内）：
  - **概念**（theory）：定义/原理/公式
  - **工具/方法**（tools）：算法、流程、实操步骤
  - **练习**（exercises）：费曼题、思考题、应用示例
- 目的：跨讲检索时按"概念/工具/练习"定位，AI 复习也更好组织。

## 每个知识点的固定结构

| 栏目 | 要求 |
|---|---|
| **定义** | 一句话，专业准确，先给概念 |
| **通俗类比** | 生活化比喻，让零基础秒懂（例：Linux 发行版≈安卓厂商定制） |
| **原理** | 展开讲，逻辑递进，不绕弯 |
| **示例** | 来自视频/转写的具体例子，可引用原句 |
| **💡 为什么重要** | 一个知识点对学习/实战的意义 |
| **⚠️ 易错点/误区** | 初学者常犯的坑 |
| **❓ 费曼思考题** | **每个知识点末尾必配**，数量按重要程度定：**核心 10 道 / 重要 8 道 / 一般 6 道**（用户 2026-08-03 定） |

## 费曼思考题写法（费曼学习法）

学生要"能把它讲给别人听"才算真懂。题目应从 4 个角度出，每道都是开放题：
1. **复述**：用自己的话向一个完全不懂的同学解释这个概念
2. **类比**：造一个生活中的比喻/例子
3. **应用/推导**：用这个概念解决一个具体问题，或推导它为什么成立
4. **联系/挑错**：这个概念和别的知识点什么关系？初学者最容易在哪错？

示例（WSL2 vs WSL1）：
- 向完全不懂电脑的同学解释 WSL1 和 WSL2 的区别（复述）
- 用"同声传译 vs 请一个真英国人住进来"的比喻说明（类比）
- 为什么 WSL2 能跑 Docker 而 WSL1 不能？（应用/推导）
- 如果我说"WSL 就是虚拟机软件"，哪里不对？（挑错）

## Frontmatter 规范（必填 8 字段，顺序固定）

> 用户 2026-08-03 定稿。所有笔记（视频/图集/文本）frontmatter 必须按下列 8 个字段的顺序书写，不得增删、不得换序。

```yaml
---
title: 主标题
source: 来源 | 源链接
author: 作者名（可附带主页链接）
duration: x分x秒（非视频一律 0分0秒）
word_count: 正文字数（整数，仅统计正文不含 frontmatter 与完整转写附录）
created: 2026/8/3 22:23（精确到分钟）
tags: [标签1, 标签2, ...]（详细丰富，最低 6 个，首个为 "{来源网站}学习笔记"，可随内容增补）
type: {来源网站小写}-ai-teaching-note（随来源网站变动）
---
```

**各字段规则**：
- **title**：主标题，能概括主题。
- **source**：`{网站}+{类型} + {源链接}`。网站与类型示例：抖音视频 / 抖音图集 / 文本整理 / b站视频 / b站图集 / youtube视频 等；源链接须能直接打开找到原视频/图集/文本；文本整理无链接可只写 `文本整理`。
- **author**：来源作者（抖音/B站/youtube UP主 等），作者名后可附主页链接；文本整理无作者写 `—`。
- **duration**：`x分x秒`；图集/文本等非视频一律写 `0分0秒`。
- **word_count**：正文字数，仅统计正文（不含 frontmatter、不含 `## 📄 完整转写` 附录），单位=字符数（不计空白）。
- **created**：精确到分钟，格式 `2026/8/3 22:23`（年/月/日 时:分）。
- **tags**：详细丰富，从关键字/核心知识点/概要提取，**最低 6 个**、上限不设、随内容逐步增加，**首个必须为 `{来源网站}学习笔记`**——按 source 的来源网站确定（见下表）；`文本整理`沿用项目默认 `抖音学习笔记`。
- **type**：随来源网站变动，格式 **`{来源网站小写}-ai-teaching-note`**（见下表）；`文本整理`沿用 `douyin-ai-teaching-note`。

**来源网站 → 首个 tag / type 映射**：

| source 来源网站 | 首个 tag | type |
|---|---|---|
| 抖音 | `抖音学习笔记` | `douyin-ai-teaching-note` |
| B站/bilibili | `B站学习笔记` | `bilibili-ai-teaching-note` |
| YouTube/youtube | `YouTube学习笔记` | `youtube-ai-teaching-note` |
| 斯坦福课程 | `斯坦福课程学习笔记` | `stanford-ai-teaching-note` |
| 其他网站 | `{其他网站名称}学习笔记` | `{其他网站名称小写}-ai-teaching-note` |
| 文本整理 | `抖音学习笔记`（项目默认） | `douyin-ai-teaching-note` |

> 课程视频专用（`organize=topic` 模式）：source 写 `{课程名} \| 本地视频`，author 写讲师名（如 Dan Jurafsky & Chris Manning），tags 首项用 `斯坦福课程学习笔记`，type 用 `stanford-ai-teaching-note`。

## 目录与交付规则（课程视频 · topic 模式）

```
NoteBooks/课程/第XX讲_标题/
  NN_XX_X_小节.md              ← 笔记平铺外层（一眼可见）
  源数据_XX_X/                  ← 每小节子文件夹，只留视频.mp4
_转写缓存/课程/第XX讲/源数据_XX_X/  ← 中间产物（wav + 转写.json + 画面OCR与GLM.txt）
```

- 笔记命名：`NN_XX_X_小节名.md`（NN=讲内序号，XX=讲次，X=小节）
- 中间产物（转写JSON/画面OCR文本）留在 `_转写缓存`，**不复制进笔记目录**
- 源数据子文件夹只放视频（保证笔记目录干净，看视频方便）
- 完整转写附录必须保留（AI 核对用）

## 章节分层生成（v1.1，2026-08-09 新增）

**生成流程（两段式）**：
1. **先列章节大纲**：读完转写后，先产出本讲的章节大纲（如 `第1章 编辑距离定义 → 第2章 计算方法 → 第3章 回溯对齐`），每章标注核心/重要/一般级别与预估费曼题数。
2. **再按大纲分层写**：逐章展开，章节内再按"概念/工具/练习"三分法组织（见铁律补充）。每章末尾可加"本章小结"。

**目的**：
- 笔记有"章节树"，像书有目录，好检索好复习。
- AI 一章一章想清楚，不会漏、不会乱、不会平铺。
- 为将来"跨课程索引 / 知识切片"打基础。

> ⚠️ 章节分层是**组织方式**，不改变 frontmatter 8 字段、不改变知识点 7 栏目、不改变完整转写附录。
